# SteppeX — «Аким на 5 часов»

Локальный AI-симулятор управления городом. Пользователь распределяет единый виртуальный бюджет между городскими инициативами, оценивает изменения районов и получает объяснение компромиссов.

## Что умеет симулятор

- Даёт всем командам одинаковый бюджет — **100 единиц** — и один синтетический набор показателей пяти районов.
- Позволяет выбрать ровно пять инициатив из каталога M1–M14 и указать район для районных инициатив.
- Проверяет стоимость, ограничения и несовместимость мер до расчёта.
- Рассчитывает Astana Quality of Life Score, изменения показателей и три альтернативные стратегии.
- Сверяет расчёт Node.js с независимым Python-симулятором. При расхождении результат не выдаётся как проверенный.
- После явного подтверждения запускает AI-анализ: модель объясняет риски на основании сигналов симулятора и предлагает сценарий для рассмотрения.

**О модели:** числовой ML-компонент — детерминированный симулятор по правилам синтетического датасета, а не обученная нейросеть. Исторических размеченных данных для обучения в задаче нет. AI-советник пишет объяснение, но не рассчитывает Score и не подменяет проверенные значения.

## Быстрый запуск для судей — без API-ключа

Демо использует реальные расчёты Node.js и Python на синтетическом датасете. Можно выбрать меры, сравнить стратегии и применить вариант **без оплаты API**. Текстовый AI-анализ и диалог без ключа недоступны: демо не подменяет их заранее написанными ответами.

### 1. Подготовьте компьютер

Нужны **Node.js 22.9+** (npm входит в установку) и **Python 3.10+**. После установки заново откройте терминал. На Windows при установке Python включите добавление в PATH.

Проверьте версии в PowerShell:

```powershell
node --version
npm.cmd --version
py -3 --version
```

Если команды `py` нет, попробуйте `python --version`. Python определяется автоматически; при необходимости укажите полный путь в `PYTHON_BIN` файла `backend/.env`.

В репозитории сохранены `backend/package-lock.json` и `frontend/package-lock.json`, поэтому ниже используется **npm**, а не `pnpm install --frozen-lockfile`. Отдельные базы данных, Docker, uvicorn и установка `backend/requirements.txt` для этой сборки не нужны.

### 2. Скачайте правильную ветку

Сборка для проверки находится в **`integrate-frontend-ml-ai`**:

- Без Git: откройте [ветку на GitHub](https://github.com/BAITC-Hacks/hack-9757e094-steppex/tree/integrate-frontend-ml-ai), нажмите **Code → Download ZIP** и распакуйте архив в новую папку. Не запускайте проект из архива и не распаковывайте поверх старой копии.
- С Git: выполните команды ниже в папке, куда хотите скачать проект:

```powershell
git clone --branch integrate-frontend-ml-ai --single-branch https://github.com/BAITC-Hacks/hack-9757e094-steppex.git
cd hack-9757e094-steppex
```

Для закрытого репозитория судье понадобится доступ к GitHub-репозиторию. Если получили ZIP, откройте распакованную папку в VS Code и выберите **Терминал → Создать терминал**.

Все следующие команды выполняйте из **корня проекта** — папки с `README.md`, `package.json`, `backend/` и `frontend/`, а не из `C:\Users\имя`.

### 3. Создайте локальный файл настроек

В GitHub лежит безопасный шаблон [backend/.env.demo](backend/.env.demo). В нём ключ пустой; настоящий файл `backend/.env` в GitHub не публикуется.

PowerShell (существующий `.env` не перезаписывается):

```powershell
if (-not (Test-Path -LiteralPath "backend/.env")) {
    Copy-Item -LiteralPath "backend/.env.demo" -Destination "backend/.env"
}
```

Если `backend/.env` уже существует, откройте его вручную: для проверки без ИИ строка должна быть `OPENAI_API_KEY=`. Не заменяйте существующий файл вслепую — там может быть ваш ключ. Проверяйте имя: **`.env`**, не `.env.txt`.

Если ключ ранее задан в переменных окружения компьютера, он имеет приоритет над файлом. Для демо без ИИ в текущем PowerShell перед запуском выполните `Remove-Item Env:OPENAI_API_KEY -ErrorAction SilentlyContinue` — это убирает переменную только из текущего сеанса, не удаляет сохранённый ключ или файл.

### 4. Установите зависимости и запустите сайт

В том же терминале по очереди выполните:

```powershell
npm.cmd --prefix backend ci
npm.cmd --prefix frontend ci
npm.cmd run dev
```

Переходите к следующей команде только если предыдущая завершилась без ошибки. Для установки зависимостей нужен интернет; после установки обычный расчёт не требует OpenAI. Корневой `npm install` не нужен.

Дождитесь сообщения **«SteppeX готов»**, затем откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). **Не закрывайте терминал**, пока проверяете сайт. В режиме без ключа статус «ИИ не настроен» ожидаем, расчёты при этом работают.

Для повторного запуска из той же папки достаточно:

```powershell
npm.cmd run dev
```

Остановить сайт и backend: **Ctrl+C** в терминале запуска. После изменения `.env` остановите и запустите приложение заново.

### macOS / Linux

Установите те же версии Node.js и Python, скачайте ветку и откройте терминал в корне проекта. Затем:

```bash
test -f backend/.env || cp backend/.env.demo backend/.env
unset OPENAI_API_KEY
npm --prefix backend ci
npm --prefix frontend ci
npm run dev
```

`unset` убирает ключ только из текущего терминала. Если `backend/.env` уже существует, для бесплатного демо проверьте, что ключ в нём тоже пустой. Версию Python можно проверить командой `python3 --version`.

### Что запускается

- Сайт: http://127.0.0.1:5173.
- API: http://127.0.0.1:3002.
- Проверка связи: http://127.0.0.1:3002/api/health — в демо ожидаются `ok: true`, `aiConfigured: false`, `mlStatus: "connected"`.
- Python запускается backend как локальный процесс, отдельный Python-сервер не нужен.

Команда `npm run dev` проверяет окружение и контрольный ML-сценарий, проверяет TypeScript, собирает сайт и запускает backend и frontend preview. Это локальная сборка без HMR: после изменений перезапустите приложение и обновите страницу.

Оба сервера слушают только `127.0.0.1`: ссылка работает **на компьютере, где запущен проект**, а не на другом ноутбуке. Если порт занят, остановите предыдущий запуск через Ctrl+C. Не меняйте порты в демо: launcher и proxy согласованы на 3002/5173.

## Сценарий демонстрации

1. Нажмите **«Загрузить пример»**.
2. Нажмите **«Рассчитать сценарий»**. Для примера ожидаются затраты **95 из 100** и Score **56.54**. Блок **«Проверка сценария»** сообщает, что результат сверил независимый ML-модуль.
3. Посмотрите таблицу изменений районов и сравните три стратегии. Вариант **«Бюджетный резерв»** в контрольном сценарии имеет Score **56.69** и оставляет **20 единиц**.
4. Кнопка **«Применить вариант»** переносит выбранную стратегию в сценарий. При ручном изменении решений прежние результаты очищаются.
5. Расчёт и подбор стратегий работают без ключа OpenAI. После настройки ключа для AI-анализа нажмите **«Спросить ИИ (платно)»** и подтвердите запрос.

## Подключение AI-советника

**Это необязательная платная часть проверки.** Нужен собственный рабочий API-ключ OpenAI с доступом к модели и доступным API-балансом. Демо-файл не содержит общего ключа команды.

1. Откройте уже созданный `backend/.env` в редакторе. Если файла нет, создайте копию `backend/.env.example` или `backend/.env.demo`.
2. Вставьте свой ключ после `OPENAI_API_KEY=` **только в локальном `backend/.env`**. Не изменяйте публикуемые `.env.demo` и `.env.example`; не добавляйте ключ во frontend, README, GitHub или чат.
3. Оставьте `OPENAI_MODEL=gpt-5-mini`, если эта модель доступна вашему API-проекту.
4. Остановите приложение через Ctrl+C, снова выполните `npm.cmd run dev` и обновите страницу. На macOS/Linux — `npm run dev`.
5. Нажмите **«Загрузить пример»**, затем **«Рассчитать сценарий»**. Введите, например: «Какие риски у моего сценария и как сохранить больше бюджета?»
6. Нажмите **«Спросить ИИ (платно)»**, подтвердите расход API и подождите до 90 секунд. Не нажимайте повторно во время ожидания.

Настройка ключа сама по себе не подтверждает его работоспособность: авторизация, доступ к модели и баланс проверяются при реальном запросе. Правило хранить ключ на сервере и не публиковать его соответствует [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/production-best-practices).

AI не вызывается при запуске сайта или обычном расчёте. Один анализ может сделать до четырёх запросов к модели. Модель самостоятельно формулирует объяснения рисков и рекомендации, используя проверенные показатели и сигналы backend. Интерфейс отдельно показывает точные числа, рассчитанные симулятором. Ответ завершается фразой **«Желаете ли вы чтобы мы помогли вам решить этот вопрос?»**

AI-объяснение — не прогноз реальных событий и не статистика Астаны. Датасет синтетический; модель не располагает данными о вероятностях кризисов или мнениях жителей. Оценка стоимости запроса приблизительная; окончательные списания смотрите в кабинете провайдера. Ошибка или прерванный запрос тоже могут расходовать токены.

### Продолжение диалога

После первого AI-анализа можно продолжить обсуждение сценария:

1. Ответ **«Да, помоги»** открывает бесплатное уточнение цели; это служебный текст, не ответ модели.
2. Выберите приоритет — общий Score, слабый район или бюджетный резерв — либо задайте свой вопрос. Перед каждым платным ответом сайт спрашивает подтверждение.
3. Советник использует контекст недавних сообщений и заново проверяет риски и стратегии текущего сценария.
4. Применение предложенного варианта не вызывает модель: сервер повторно проверяет решение симулятором и обновляет диалог.
5. Ручное изменение мер, новый расчёт или обновление страницы начинают новый диалог. Кнопка **«Да, помоги · бесплатно уточнить цель»** доступна без вызова модели.

Диалоги хранятся в памяти backend до тридцати минут бездействия и сбрасываются при перезапуске. Агенту передаётся ограниченная история последних сообщений; в одном диалоге разрешено до шести платных ответов. Повтор успешно обработанного запроса с тем же `requestId` возвращает сохранённый ответ без повторного вызова модели. Автоматических повторов запросов нет.

В приложении нет пользовательских аккаунтов. Не публикуйте идентификатор диалога и не выставляйте локальный backend в интернет без авторизации.

## Как устроен расчёт

```text
frontend (React)
    │ /api через локальный proxy
    ▼
backend (Node.js) ──────► AI-советник (по запросу пользователя)
    │                      инструменты сравнения и проверки рисков
    ├──► Node.js engine: правила, бюджет, Score, стратегии
    └──► ml/bridge.py → ml/simulator.py: независимый пересчёт в Python
```

Backend сравнивает Score, бюджет, критические значения, средний балл, оценки районов и показатели, возвращённые Python. При ошибке Python или расхождении чисел сценарий блокируется. Python-процесс ограничен десятью секундами; ключ OpenAI ему не передаётся.

Основные части проекта:

- `frontend/` — интерфейс симулятора;
- `backend/src/engine.js` — бизнес-правила, расчёт и поиск стратегий;
- `backend/src/agent.js` — AI-советник и проверка его отчёта;
- `backend/data/city.json` — исходный синтетический датасет;
- `ml/simulator.py` и `ml/bridge.py` — независимый Python-расчёт;
- `backend/test/` и `ml/test_simulator.py` — автоматические проверки.

При изменении датасета обновите Node- и Python-реализации согласованно: независимая проверка намеренно отклонит несовпадающие расчёты.

## Проверки

Из корневой папки (на macOS/Linux замените `npm.cmd` на `npm`):

```powershell
npm.cmd test
npm.cmd --prefix frontend run build
```

Чтобы выполнить smoke-проверку, сначала запустите приложение в отдельном терминале командой `npm.cmd run dev`, затем выполните:

```powershell
npm.cmd run smoke
```

Smoke-проверка обращается к локальному frontend proxy, backend и Python, но не к OpenAI. Дополнительно Python-тесты можно запустить отдельно:

```powershell
py -3 -m unittest discover -s ml -p "test_*.py"
```

На macOS/Linux используйте `python3` вместо `py -3`. Обычные тесты используют подставной AI-провайдер и не расходуют API-баланс.

## Диагностика

- **`ENOENT ... package.json`** — терминал открыт не в корне проекта. Перейдите в папку с `README.md`, `package.json`, `backend/` и `frontend/`.
- **`npm.ps1` запрещён политикой PowerShell** — используйте `npm.cmd`, как в командах выше; менять политику безопасности не требуется.
- **Команда `node`, `npm` или Python не найдена** — установите нужную программу и заново откройте терминал; проверьте версии из первого шага.
- **Ошибка `pnpm ... --frozen-lockfile`** — используйте приведённые выше команды `npm.cmd --prefix backend ci` и `npm.cmd --prefix frontend ci`: в этой ветке npm lock-файлы.
- **Установка зависимостей завершилась ошибкой** — не переходите к запуску; проверьте интернет, версию Node.js и скачайте свежую копию ветки в новую папку. Не удаляйте lock-файлы для обхода ошибки.
- **`ML_UNAVAILABLE`** — проверьте версию Python; при необходимости задайте полный путь к нему в `PYTHON_BIN` файла `backend/.env`.
- **Порт занят** — остановите предыдущую копию приложения через Ctrl+C.
- **Backend недоступен** — оставьте окно запуска открытым и посмотрите сообщения в терминале; health endpoint: http://127.0.0.1:3002/api/health.
- **AI не настроен** — проверьте `backend/.env` и перезапустите приложение. Ключ не нужен для числовой симуляции.
- **Не открывается API через сайт** — используйте http://127.0.0.1:5173, а не файл `frontend/dist/index.html` напрямую.
