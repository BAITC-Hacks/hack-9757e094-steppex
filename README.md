# SteppeX — «Аким на 5 часов»

Объединённое веб-приложение команды: React frontend, Node.js backend с ИИ-советником и независимая проверка расчётов Python-модулем ML. Сборка предназначена для локальной демонстрации.

## Открыть и попробовать

После запуска откройте http://127.0.0.1:5173.
Нажмите **Загрузить пример**, затем **Рассчитать сценарий**.
Ожидаются: расходы 95 из 100, Score 56.54, отметка «ML-расчёт подтверждён».
Ниже есть таблица районов и три стратегии. «Бюджетный резерв» даёт Score 56.69 и остаток 20.
Кнопка «Применить вариант» переносит проверенный набор в текущий сценарий.
После любого ручного изменения старые результаты очищаются.

Расчёт, проверка Python и сравнение стратегий не используют OpenAI API.
Кнопка ИИ-анализа заблокирована, пока на backend не настроен ключ.

## Запуск в PowerShell

Откройте терминал в **этой папке**, не в домашней папке Windows.
Нужен Node.js 22.9+ и Python 3.10+. Python определяется автоматически; при необходимости укажите путь в `PYTHON_BIN` в `backend/.env`.

Первый запуск на другом компьютере:

```powershell
npm.cmd --prefix backend ci
npm.cmd --prefix frontend ci
npm.cmd run dev
```

После установки зависимостей для повторного запуска достаточно `npm.cmd run dev`. На macOS/Linux используйте `npm` вместо `npm.cmd`.

Команда проверяет Node.js, свободные порты, Python и контрольный расчёт ML, затем проверяет TypeScript, собирает сайт и запускает backend. Только после готовности backend запускается frontend. Дождитесь строки **«SteppeX готов»**.

Локальные адреса:
- frontend: http://127.0.0.1:5173;
- backend: http://127.0.0.1:3002;
- Python вызывается backend локально, отдельный Python-сервер не нужен.

Старый backend на порту 3001 не используется и не останавливается этой сборкой.
Оба новых сервера слушают только 127.0.0.1. Ctrl+C в окне запуска останавливает их.
Если порты заняты, сначала остановите предыдущий запуск этой сборки.

Это собранный локальный preview, без HMR: после изменения frontend перезапустите команду и обновите страницу.
TypeScript + Rollup используются через программный интерфейс Vite без обхода домашних каталогов нативным esbuild.
Обычный `vite.config.ts` сохранён, но этот launcher использует `frontend/local-vite.mjs`. Оба используют единые настройки proxy из `frontend/vite.shared.mjs`. Устаревшие `vite.config.js` и `vite.config.d.ts` удалены; TypeScript-конфигурация больше их не генерирует.

`npm.cmd run dev` из папки `frontend` также запускает всю связку. `npm.cmd run preview` в этой папке запускает только сайт и требует отдельно работающего backend.

### Если запуск не удался

- Обновляясь через ZIP, распаковывайте его в **новую папку**, не поверх старой: иначе удалённый конфиг может остаться на диске.
- `ML_UNAVAILABLE`: проверьте `python --version` или `py -3 --version`. Нужен Python 3.10+. Если он установлен, но не находится, укажите полный путь к исполняемому файлу в `PYTHON_BIN` в `backend/.env`. Без Python запуск намеренно останавливается до открытия сайта; непроверенные расчёты не выдаются.
- «Порт занят»: остановите предыдущий запуск через Ctrl+C. Не запускайте две копии одновременно.
- «Backend на порту 3002 недоступен»: оставьте терминал запуска открытым, проверьте его сообщения. Диагностика: http://127.0.0.1:3002/api/health.
- «Вместо API получена страница сайта»: проверьте, что используется новая копия проекта и настроен proxy `/api`. Не открывайте `dist/index.html` напрямую.
- При временном сбое начальные GET-запросы повторяются до трёх раз. Платный ИИ-анализ автоматически не повторяется.

Ключ OpenAI не нужен для запуска, проверки окружения и числовых расчётов.

## Как соединены три части

- Frontend команды сохранён как основа оформления; его API-запросы переведены на относительные `/api/...` через локальный proxy.
- Временные бюджет 1000, меры t1/g1 и локальная формула интерфейса заменены каталогом организаторов: бюджет 100, меры M1–M14, пять районов.
- Node-backend проверяет правила, вычисляет подробные показатели и ищет стратегии.
- `ml/simulator.py` команды реально запускается через `ml/bridge.py`. Он независимо вычисляет показатели для выбранного сценария и предложенных вариантов.
- Перед выдачей результата сверяются Score, база, стоимость, остаток, критические значения, среднее, баллы районов и все показатели. Python округляет до сотых, поэтому допуск сравнения — 0.005001.
- При расхождении или недоступном Python возвращается ошибка ML, а результат не выдаётся как успешный.
- ИИ-агент использует эту же проверенную связку. ML здесь — детерминированный симулятор, не обученная нейросеть.

Процесс Python ограничен десятью секундами; OpenAI-ключ в его окружение не передаётся.
Python-запуск синхронный и подходит для локальной демонстрации; для публичной нагрузки нужен отдельный worker/сервис.
При замене датасета необходимо синхронно обновить Python-модуль, иначе проверка заблокирует отличающиеся результаты.

## Включение настоящего ИИ (не обязательно)

1. Создайте **в этой сборке** файл `backend/.env` по `backend/.env.example`.
2. Укажите `OPENAI_API_KEY`. Не пересылайте ключ в чат и не добавляйте его в GitHub/frontend.
3. По умолчанию используется `OPENAI_MODEL=gpt-5-mini`. Модель должна быть доступна вашему API-проекту.
4. Перезапустите `npm.cmd run dev`, обновите страницу.
5. Выберите допустимые пять решений, нажмите **Получить ИИ-анализ (платно)** и подтвердите запуск.

Наличие настройки ключа не доказывает его работоспособность. Авторизация, доступ к модели и баланс проверяются только реальным запросом.
За один анализ агент делает до четырёх запросов модели. Автоматические платные запросы при открытии сайта отсутствуют.
Живой ответ модели проверен локально: один анализ успешно завершился за три запроса модели. Автоматические тесты используют подставной провайдер; ключ и ответ пользователя в репозиторий не включены.

ИИ самостоятельно объясняет риски на основе проверяемых сигналов симулятора; отдельный шаблонный список рисков текущего сценария не дублируется. Ответ ИИ заканчивается вопросом: «Желаете ли вы чтобы мы помогли вам решить этот вопрос?» Проверка чисел и ссылок не гарантирует точности всех формулировок модели. В инструкции отдельно запрещено обещать быстрый эффект без проверки лагов.

### Диалог с советником

После первого ИИ-анализа появляется история и поле следующего вопроса.

1. Нажмите **«Да, помоги»**: интерфейс бесплатно уточнит цель. Этот служебный ответ явно помечен как не использующий ИИ.
2. Выберите общий Score, слабый район или бюджетный резерв, либо задайте свой вопрос. Перед каждым содержательным ответом запрашивается подтверждение расхода API.
3. Агент получает контекст предыдущих сообщений и заново вызывает инструменты сравнения стратегий и проверки рисков для текущего сценария.
4. Нажмите **«Применить вариант · без ИИ»**: сервер повторно проверит сохранённый вариант, обновит решения и контекст. Само применение не обращается к модели.
5. Можно продолжить обсуждение уже изменённого набора. Ручной выбор мер, новый расчёт или обновление страницы сбрасывают диалог в интерфейсе.

Контекст хранится в памяти backend до 30 минут бездействия и теряется при перезапуске. Для модели передаются последние восемь сообщений с ограниченной длиной, а не бесконечная история. Максимум шесть платных ответов, включая первый; одновременно хранится до пятидесяти диалогов. В истории интерфейса предыдущие отчёты относятся к сценариям на момент их создания.

История, решения и варианты берутся с сервера, а не из сообщения браузера. Проверяется версия диалога; старые варианты нельзя применить к новому состоянию. Повтор успешно выполненного сообщения с тем же `requestId` возвращает сохранённый результат без нового обращения к модели. Автоматических повторов платных запросов нет; ошибки провайдера всё равно могут сопровождаться списанием.

Это локальная демонстрация без пользовательских аккаунтов: идентификатор диалога нельзя публиковать, а сервер нельзя открывать в интернет без авторизации. Реализация использует ручную передачу контекста в Responses API и `store: false`; схема работы основана на [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/conversation-state). Между пользовательскими репликами передаётся ограниченное текстовое резюме проверенного отчёта; внутри одного анализа сохраняются полные элементы tool-calling через SDK.

Новый диалог проверен в браузере с подставным провайдером и настоящим Python, без платных вызовов. Полноценный живой многошаговый ответ OpenAI пока требует отдельной проверки.

### Стоимость

Стандартный тариф gpt-5-mini, проверен 2026-09-23:
- входные токены: $0.25 / 1 000 000;
- кэшированные входные: $0.025 / 1 000 000;
- выходные, включая reasoning: $2 / 1 000 000.

Пример для **всего анализа, а не одного внутреннего запроса**: 30 000 некэшированных входных и 5 000 выходных токенов = $0.0175.
Это иллюстрация, не обещание фиксированной цены. Один анализ включает повторную передачу контекста и результатов инструментов.
Успешный ответ API содержит `usage`: суммарные токены всех шагов и оценку стоимости; интерфейс показывает её.
Для другой модели сумма в долларах не вычисляется автоматически.
Неудавшиеся/оборванные анализы тоже могут расходовать токены; окончательные списания проверяйте у провайдера.
В одном локальном пробном анализе интерфейс показал оценку $0.0064 за три запроса модели. Это оценка конкретного запуска, не фиксированная стоимость будущих запросов и не подтверждение списания по счёту провайдера.

Источник: https://developers.openai.com/api/docs/models/gpt-5-mini

## Проверки

```powershell
npm.cmd test
npm.cmd --prefix frontend run build
npm.cmd run smoke
```

Последняя команда требует запущенную сборку. Она проверяет frontend proxy, backend, реальный Python и обработку невалидного сценария.
Ни одна из этих команд не обращается к OpenAI.

Дополнительно проверены в браузере: пример организаторов, три стратегии, применение резервного варианта, смена района со сбросом результатов и блокировка превышенного бюджета.
В автоматических проверках есть отдельный корпус из 120 валидных сценариев с покрытием всех 14 мер.

## Происхождение

Frontend и ML загружены из `main` репозитория BAITC-Hacks/hack-9757e094-steppex, коммит `5e9450412709150afa7da55712ab031406574857`.
Backend основан на ранее проверенной реализации из ветки `backend-ai`; здесь добавлены интеграция с UI, проверка Python и учёт использования модели.
Временный FastAPI-прототип `backend/app.py` с бюджетом 1000 сохранён для истории и намеренно не запускается: это другой набор правил и контракт. Для текущего приложения не нужен `uvicorn` или установка `backend/requirements.txt`.
Сохранены последние улучшения команды в `ml/simulator.py` и пять Python-тестов в `ml/test_simulator.py`.
Подробности исходного backend: [backend-node.md](docs/backend-node.md).
Контракт и локальные дополнения: [backend-api.md](docs/backend-api.md).

Не публикуйте сборку напрямую в интернет: она предназначена для локальной проверки и не содержит полноценной пользовательской авторизации.
