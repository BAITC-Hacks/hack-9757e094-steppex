# SteppeX — «Аким на 5 часов»

Hackathon team repository for SteppeX.

Backend и AI-агент «Советник акима» для симулятора управления городом. Пользователь выбирает пять мероприятий; сервер проверяет правила, вычисляет Astana Quality of Life Score и сравнивает альтернативные стратегии. LLM объясняет компромиссы, ссылается на вычисленные риски и рекомендует проверенный вариант.

Backend подключён к frontend и независимому Python-симулятору. Для запуска всей сборки используйте [корневой README](../README.md); ниже описаны backend и его [контракт API](backend-api.md).

## Быстрый запуск

Нужен Node.js 22.9 или новее и Python 3.10+. Команды выполняются из корня репозитория:

```sh
cd backend
npm ci
npm test
npm run demo
npm start
```

При отдельном запуске порт по умолчанию — `3001`; шаблон `.env` и общий launcher используют `3002`. Проверка запуска: `GET /api/health`. Каталог для frontend: `GET /api/catalog`.

Без API-ключа все числовые расчёты, валидация, сравнение и поиск стратегий работают локально. `POST /api/analyze` явно отвечает `503 AI_NOT_CONFIGURED` и не имитирует ответ модели.

### Включить настоящий ИИ

1. Создайте файл `backend/.env` по образцу `backend/.env.example`.
2. Укажите в нём серверный `OPENAI_API_KEY` и доступную вашему API-проекту модель в `OPENAI_MODEL`.
3. Перезапустите `npm start` и отправьте пример из [документации API](backend-api.md) на `/api/analyze`.

Модель по умолчанию — `gpt-5-mini`. Она должна поддерживать Responses API, function calling и Structured Outputs. Подписка ChatGPT не заменяет доступ к API. Ключ не передаётся в frontend, в запросы пользователя или в репозиторий; `.env` исключён через `.gitignore`.

`/api/health` сообщает только наличие настройки ключа, а не успешность авторизации у провайдера. Один живой анализ проверен в объединённой сборке; результаты и ограничения описаны в корневом README. Автоматические проверки агента используют подставной ответ провайдера и реальные локальные инструменты симулятора.

## Данные и правила

Числа взяты из документа организаторов [«Датасет районов»](https://docs.google.com/document/d/1Uc-GdGoKhDY-spu8V50-ZMm33t2CjYLP/edit) и перенесены в `backend/data/city.json`. Это синтетические данные для игры, не проверенная статистика реальной Астаны.

- Пять районов: Есиль, Алматы, Сарыарка, Байконур, Нура.
- Десять показателей, все от нуля до ста; больше означает лучше.
- Четырнадцать мероприятий, бюджет — сто условных единиц, горизонт — восемь кварталов.
- Ровно пять разных мер, максимум две из одного направления.
- Для районной меры обязателен район; для городской он отсутствует или `null`.
- Учитываются лаги, три синергии и три несовместимости. Перерасход запрещён.

Общее задание описывает пять направлений. Подробный датасет уточняет правило выбора: охватывать каждое направление необязательно; допускаются две меры одного направления. Его контрольный пример тоже использует это правило. Backend следует подробным правилам датасета.

Все пользователи получают один серверный снимок данных с `datasetVersion`. Браузер не может переопределить бюджет, эффекты или веса в своём запросе. Для замены датасета администратор задаёт `DATASET_PATH`, синхронно обновляет данные Python-симулятора и перезапускает сервер для всех пользователей; расхождения расчётов блокируются.

## Проверяемая модель

Реализованный эффект меры: `effect × (8 − lag) / 8`. Эффекты всех мер и фиксированные синергии сначала суммируются, затем каждый показатель ограничивается диапазоном `[0, 100]`.

```text
D(d) = сумма(weight(k) × indicator(d,k))
D_avg = сумма(populationShare(d) × D(d))
Score = 0.7 × D_avg + 0.3 × min(D(d)) − count(indicator(d,k) < 40)
```

Округление не участвует в расчёте штрафов. API возвращает значения с точностью до шести десятичных знаков, сайт может показывать два.

Контрольные результаты, проверенные кодом:

| Сценарий                                                                                                              | Стоимость |    Score |
| --------------------------------------------------------------------------------------------------------------------- | --------: | -------: |
| База без действий (справочная)                                                                                        |         0 | 52.55768 |
| Пример организаторов: школа, поликлиника и освещение в Нуре; платформа обращений по городу; чистое топливо в Сарыарке |        95 | 56.54307 |

Невалидный пользовательский набор никогда не получает Score. База без действий — внутренний справочный расчёт, а не разрешение отправить меньше пяти решений.

`measures[].marginalScore` показывает, насколько упадёт итог при исключении конкретной меры вместе с её синергиями. Эти вклады нельзя складывать: минимум по районам и критические пороги делают формулу нелинейной.

## Чем полезен агент

Агент вызывает локальные инструменты через OpenAI function calling:

1. `compare_strategies`: вычисляет альтернативы с приоритетом общего Score, слабого района и бюджетного резерва.
2. `inspect_risks`: получает оставшиеся критические показатели, ухудшения, лаги и небольшой резерв.
3. При необходимости `evaluate_scenario`: проверяет предложенный моделью полный набор мер.
4. Возвращает структурированный русский отчёт: сильные стороны, риски с идентификаторами доказательств, компромиссы и рекомендации.

Каждая стратегия изменяет не более одного решения: заменяет меру или переносит её в другой район. Это ограниченный поиск соседних вариантов, не доказательство глобального оптимума. «Бюджетный резерв» сохраняет или улучшает текущий Score и не увеличивает число критических показателей. «Поддержка слабого района» максимизирует минимум по районам, не увеличивая число критических показателей. Разные цели могут привести к одинаковому набору.

В текстовых полях отчёта модель не пишет цифры; точные значения берутся из серверных полей `simulation` и `strategies`. Числовые утверждения и несуществующие ссылки на риски в ответе модели отклоняются. Смысловые ошибки LLM всё равно возможны; проверяемые числовые карточки должны оставаться видимыми пользователю.

Дополнительные аналитические флаги «близко к порогу» (от сорока до сорока пяти) и «малый резерв» (менее десятой доли бюджета) — явно заданные эвристики приложения. Они не меняют официальный Score и не являются вероятностями реальных событий.

## Интеграция и проверка

Стек: JavaScript, Node.js, Express, OpenAI SDK, Zod. Зависимости зафиксированы в `backend/package-lock.json`. Тесты используют встроенный `node:test` и запускаются через `npm test`.

Проверяются контрольные числа организаторов, бюджет, повторные меры, районы, лимит направления, несовместимости, лаги, синергии, критический порог, независимость от порядка, стратегии, API и обработка ответов модели.

Frontend берёт каталог и ограничения из API, показывает бюджет и показатели, отправляет выбранные ID. Не копируйте формулу в браузер как источник итогового результата. Ответы модели отображайте как текст, а не через небезопасный `innerHTML`.

По умолчанию backend слушает только `127.0.0.1`. `FRONTEND_ORIGINS` задаёт разрешённые адреса сайта. Для развёртывания установите `HOST=0.0.0.0`, секреты и адрес frontend в окружении хостинга. Лимитер рассчитан на один серверный процесс. Публичный многопользовательский запуск потребует авторизации, устойчивых квот и хранения результатов; текущая версия предназначена для демонстрации команды.

## Структура

```text
backend/
  data/city.json        — исходные таблицы и правила
  src/engine.js         — валидация, формула, риски, стратегии
  src/agent.js          — цикл инструментов и проверка отчёта LLM
  src/app.js            — HTTP API и ошибки
  src/server.js         — окружение и запуск
  scripts/demo.js       — воспроизводимый расчёт без ключа
  test/                — проверки модели и API
docs/backend-api.md     — контракт для frontend-разработчика
```
