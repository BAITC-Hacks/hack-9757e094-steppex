# План разработки

## Этап 1. Подготовка и фиксация требований
**Цель:** согласовать структуру проекта и архитектуру решения.

**Что делаем:**
- зафиксировать бюджет и набор правил;
- определить 5 категорий решений;
- определить логику расчёта score;
- согласовать форматы данных и API.

**Результат:**
- единая спецификация проекта;
- договорённости по структуре данных и ролям.

## Этап 2. Создание базового UI
**Цель:** собрать рабочий интерфейс симулятора.

**Что делаем:**
- настроить React + Vite проект;
- сделать главную страницу;
- сверстать панели с решениями и бюджетом;
- добавить валидацию превышения бюджета.

**Результат:**
- работающий пользовательский интерфейс без логики расчёта.

## Этап 3. Backend и API
**Цель:** обеспечить стабильную связку между фронтендом и ML.

**Что делаем:**
- настроить FastAPI;
- описать эндпоинты для районов, мероприятий и симуляции;
- ввести валидацию входных данных;
- соединить backend с ML-модулем.

**Результат:**
- готовый API для симуляции и расчёта сценария.

## Этап 4. ML-логика и AI-объяснение
**Цель:** получить итоговый score и интерпретацию.

**Что делаем:**
- подготовить синтетический датасет;
- реализовать функцию расчёта score;
- добавить моделирование последствий решений;
- сформировать текстовое объяснение: сильные стороны, риски, рекомендации.

**Результат:**
- корректный score и человекочитаемое резюме сценария.

## Этап 5. Сборка и демо
**Цель:** сделать продукт презентабельным и проверяемым.

**Что делаем:**
- свести фронтенд, backend и ML в один рабочий стек;
- протестировать сценарии бюджетного ограничения;
- отладить вывод score и AI-объяснения;
- подготовить README и деплойную инструкцию.

**Результат:**
- рабочий MVP, готовый к демонстрации.

## Критерии готовности MVP
- одинаковый стартовый бюджет для всех пользователей;
- 5 решений по категориям;
- запрет на превышение бюджета;
- итоговый Astana Quality of Life Score;
- AI-объяснение сценария.
