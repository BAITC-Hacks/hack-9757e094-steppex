# Текущий backend

Объединённая сборка использует Node.js (`src/server.js`) и локальный Python-симулятор (`../ml/bridge.py`). Запускайте `npm.cmd run dev` из корня репозитория. Установка и настройка ключа: [основной README](../README.md). Контракт: [backend-api.md](../docs/backend-api.md).

`app.py` и `requirements.txt` сохранены как прежний FastAPI-прототип; они не используются текущим frontend. Ниже сохранён первоначальный план, а не описание действующего API.

# Backend

## Назначение
Бэкенд отвечает за бизнес-логику: хранение данных, проверку бюджета, расчёт сценария и обмен данными с ML-модулем.

## Стек
- Python
- FastAPI
- Pydantic
- Uvicorn
- SQLAlchemy (при необходимости)

## Основные задачи
- API для получения списка районов и мероприятий;
- валидация бюджета и ограничений;
- расчёт итоговых показателей по выбранным решениям;
- интеграция с ML-сервисом для AI-объяснения;
- подготовка ответа для фронтенда в формате JSON.

## Основные эндпоинты
- GET /api/health
- GET /api/regions
- GET /api/interventions
- POST /api/simulate
- GET /api/leaderboard (опционально)

## Логика работы
1. Фронтенд отправляет выбранные решения.
2. Бэкенд валидирует бюджет и формирует модель состояния города.
3. Данные отправляются в ML-сервис для расчёта score и интерпретации.
4. Бэкенд возвращает итоговые показатели, риски и рекомендации.
